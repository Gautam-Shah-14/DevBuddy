## فوری انسٹالیشن (Quick Install)

> **Docker اختیاری ہے، لازمی نہیں۔** `devbuddy` ایک سادہ پائتھون (Python) کنسول اسکرپٹ ہے — یہ
> آپ کی اپنی مشین پر، آپ کے اپنے لوکل Ollama (یا OpenAI/Anthropic/کسی بھی پرووائیڈر) کے ساتھ،
> بغیر کسی کنٹینر کے چلتا ہے۔ اس ریپوزٹری میں موجود `docker-compose.yml` صرف *gateway* اور
> *dashboard* سروسز کو کھڑا کرتا ہے (ہمیشہ آن میسجنگ-پلیٹ فارم برج اور ویب UI) — ان لوگوں کے لیے
> جو اسے بیک گراؤنڈ سروس کے طور پر چلانا چاہتے ہیں جو ٹیلی گرام، ڈسکارڈ وغیرہ سے قابل رسائی ہو۔
> اگر آپ صرف ٹرمینل سے بات چیت کرنا چاہتے ہیں، تو Docker کی بالکل ضرورت نہیں۔

اس ریپوزٹری کا ابھی تک اپنا کوئی ہوسٹڈ انسٹالر نہیں ہے — سورس سے چلائیں:

<div dir="ltr">

```bash
git clone https://github.com/Gautam-Shah-14/DevBuddy.git && cd DevBuddy
source ./activate      # ایک لوکل Python/Node ماحول تیار اور ایکٹیویٹ کرتا ہے (Docker کی ضرورت نہیں)
devbuddy                # بات چیت شروع کریں — ڈیفالٹ طور پر آپ کا لوکل Ollama استعمال ہوتا ہے
```

</div>

`source ./activate` کے لیے Python 3.14 (پروجیکٹ کا اصل ورژن — پرانے ورژنز اس کی ڈیپینڈینسیز کو
حل ہی نہیں کر سکتے) اور Node.js درکار ہیں؛ PM ٹول-منیجر کے مکمل ورک فلو (ایکٹیویشن، روزانہ
استعمال، ڈیپینڈینسی تبدیلیاں، ٹیسٹ چلانا) کے لیے `AGENTS.md` دیکھیں۔

### ونڈوز / اینڈرائیڈ

پرانے ون-کلک ہوسٹڈ انسٹالرز (`install.sh` / `install.ps1`، Termux کا APT ریپوزٹری) نوس ریسرچ کے
اپنے ڈومین کی طرف اشارہ کرتے تھے اور ابھی اس fork کے لیے کام نہیں کرتے۔ نیٹو ونڈوز اور
Termux/اینڈرائیڈ دونوں اوپر دیے گئے سورس طریقے سے کام کرتے ہیں؛ صرف یہاں ان کے لیے ابھی ایک
پیکیجڈ ون-لائنر موجود نہیں ہے۔

## آغاز کریں (Getting Started)

<div dir="ltr">

```bash
devbuddy              # انٹرایکٹو CLI — بات چیت شروع کریں
devbuddy model        # اپنا LLM پرووائیڈر اور ماڈل منتخب کریں
devbuddy tools        # کنفیگر کریں کہ کون سے ٹولز ایکٹو ہیں
devbuddy config set   # انفرادی کنفگ (config) ویلیوز سیٹ کریں
devbuddy config get   # انفرادی کنفگ ویلیوز پرنٹ کریں
devbuddy gateway      # میسجنگ گیٹ وے شروع کریں (ٹیلی گرام، ڈسکارڈ، وغیرہ)
devbuddy setup        # مکمل سیٹ اپ وزرڈ چلائیں (یہ سب کچھ ایک ساتھ کنفیگر کر دے گا)
devbuddy claw migrate # OpenClaw سے مائیگریٹ کریں (اگر آپ OpenClaw سے آ رہے ہیں)
devbuddy update       # لیٹسٹ ورژن پر اپ ڈیٹ کریں
devbuddy doctor       # کسی بھی مسئلے کی تشخیص کریں
```

</div>

### ڈیٹا اور کنفیگریشن کا مقام

تمام لوکل ڈیٹا — `config.yaml`، `.env` کی حساس معلومات، سیشن ڈیٹابیس، مہارتیں (skills)، لاگز، نامزد
پروفائلز — `~/.devbuddy` میں رہتا ہے (نیٹو ونڈوز پر `%LOCALAPPDATA%\devbuddy`)۔ یہ کوڈ میں ایک
ہی جگہ سے کنٹرول ہوتا ہے (`devbuddy_constants._get_platform_default_hermes_home()`)؛
`HERMES_HOME` انوائرمنٹ ویری ایبل اب بھی پہلے کی طرح اس کو اوور رائیڈ کر سکتا ہے، اگر آپ ڈیٹا کو
کسی اور جگہ (دوسری ڈرائیو، سنک شدہ فولڈر، کنٹینر والیوم وغیرہ) محفوظ کرنا چاہتے ہیں:

<div dir="ltr">

```bash
export HERMES_HOME=/path/to/your/data   # اختیاری اوور رائیڈ؛ ڈیفالٹ ~/.devbuddy
devbuddy doctor                          # تصدیق کرتا ہے کہ یہ کہاں سے پڑھ/لکھ رہا ہے
```

</div>

`devbuddy doctor` اور `devbuddy profile list` دونوں فعال ہوم (home) پاتھ پرنٹ کرتے ہیں اگر آپ
تصدیق کرنا چاہیں کہ چیزیں واقعی کہاں محفوظ ہوئیں۔

## CLI بمقابلہ میسجنگ فوری حوالہ

ڈیو بڈی کے دو بنیادی انٹر فیس ہیں: آپ ٹرمینل UI کو `devbuddy` کے ساتھ شروع کریں، یا گیٹ وے چلا کر اس
کے ساتھ ٹیلی گرام، ڈسکارڈ، سلیک، واٹس ایپ، سگنل، یا ای میل کے ذریعے بات کریں۔ جب آپ کسی بات چیت میں
ہوتے ہیں، تو بہت سی سلیش (slash) کمانڈز دونوں انٹرفیسز میں ایک جیسی ہوتی ہیں۔

<div dir="ltr">

| کارروائی (Action)                         | سی ایل آئی (CLI)                              | میسجنگ پلیٹ فارمز (Messaging platforms)                                          |
| --------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------- |
| بات چیت شروع کریں                       | `devbuddy`                                    | `devbuddy gateway setup` اور `devbuddy gateway start` چلائیں، پھر بوٹ کو میسج بھیجیں |
| نئی بات چیت شروع کریں                   | `/new` یا `/reset`                            | `/new` یا `/reset`                                                               |
| ماڈل تبدیل کریں                         | `/model [provider:model]`                     | `/model [provider:model]`                                                        |
| پرسنلٹی (Personality) سیٹ کریں           | `/personality [name]`                         | `/personality [name]`                                                            |
| پچھلی باری کو دوبارہ یا منسوخ (undo) کریں | `/retry`، `/undo`                             | `/retry`، `/undo`                                                                |
| کانٹیکسٹ (context) کمپریس کریں / استعمال چیک کریں | `/compress`، `/usage`، `/insights [--days N]` | `/compress`، `/usage`، `/insights [days]`                                        |
| مہارتیں (Skills) براؤز کریں             | `/skills` یا `/<skill-name>`                  | `/<skill-name>`                                                                  |
| موجودہ کام کو روکیں                     | `Ctrl+C` دبائیں یا نیا میسج بھیجیں            | `/stop` یا نیا میسج بھیجیں                                                       |
| پلیٹ فارم کے لحاظ سے سٹیٹس              | `/platforms`                                  | `/status`، `/sethome`                                                            |

</div>

صرف نام تبدیل کیا گیا ہے اور ڈیفالٹ طور پر `~/.hermes` کے بجائے `~/.devbuddy` کی طرف اشارہ کرتا ہے۔
اس ریپوزٹری میں موجود `AGENTS.md` اس fork کے اپنے کوڈ ڈھانچے اور کنونشنز کا مرکزی حوالہ ہے۔

## OpenClaw سے منتقلی

اگر آپ OpenClaw سے منتقل ہو رہے ہیں، تو ڈیو بڈی آپ کی سیٹنگز، یادیں (memories)، مہارتیں (skills)، اور API کیز کو خود بخود امپورٹ کر سکتا ہے۔

**پہلی بار سیٹ اپ کے دوران:** سیٹ اپ وزرڈ (`devbuddy setup`) خود بخود `~/.openclaw` کو پہچان لیتا ہے اور کنفیگریشن شروع ہونے سے پہلے مائیگریٹ (migrate) کرنے کا آپشن دیتا ہے۔

**انسٹالیشن کے بعد کسی بھی وقت:**

<div dir="ltr">

```bash
devbuddy claw migrate              # انٹرایکٹو مائیگریشن (مکمل پری سیٹ)
devbuddy claw migrate --dry-run    # جائزہ لیں کہ کیا کیا مائیگریٹ ہوگا
devbuddy claw migrate --preset user-data   # حساس معلومات (secrets) کے بغیر مائیگریٹ کریں
devbuddy claw migrate --overwrite  # موجودہ متصادم فائلوں کو اوور رائٹ کریں
```

</div>

جو چیزیں امپورٹ ہوتی ہیں:

- **SOUL.md** — پرسونا (persona) فائل
- **میموریز (Memories)** — MEMORY.md اور USER.md کی اندراجات
- **مہارتیں (Skills)** — صارف کی بنائی گئی مہارتیں → `~/.devbuddy/skills/openclaw-imports/`
- **کمانڈ الاؤ لسٹ (allowlist)** — منظوری کے پیٹرنز (approval patterns)
- **میسجنگ سیٹنگز** — پلیٹ فارم کنفیگریشنز، اجازت یافتہ صارفین، ورکنگ ڈائریکٹری
- **API کیز** — الاؤ لسٹ شدہ حساس معلومات (ٹیلی گرام، OpenRouter، OpenAI، Anthropic، ElevenLabs)
- **TTS اثاثے** — ورک اسپیس کی آڈیو فائلیں
- **ورک اسپیس کی ہدایات** — AGENTS.md (`--workspace-target` کے ساتھ)

تمام آپشنز دیکھنے کے لیے `devbuddy claw migrate --help` استعمال کریں، یا انٹرایکٹو ایجنٹ کی مدد سے مائیگریٹ کرنے کے لیے `openclaw-migration` سکل کا استعمال کریں (جس میں ڈرائی رن (dry-run) پریویوز شامل ہیں)۔

## اس fork کے بارے میں

یہ ڈیو بڈی پروجیکٹ کے لیے ایک نئے سرے سے لکھنے کی سمت ہے (پہلے یہ ایک آزاد TypeScript CLI تھا)۔
اس چھوٹے کوڈ بیس کو بڑھاتے رہنے کے بجائے، اب یہ Hermes Agent کے اپنے (کہیں زیادہ بڑے، MIT لائسنس)
ایجنٹ پلیٹ فارم پر بنایا گیا ہے، نیا نام دیا گیا ہے، اور ڈیفالٹ طور پر `~/.devbuddy` کی طرف اشارہ کرتا
ہے۔ Hermes کی اپنی برانڈنگ ابھی تک کوڈ کے ہر گوشے سے صاف نہیں کی گئی — کمنٹس، چند تھرڈ-پارٹی
انٹیگریشنز کے ڈیفالٹ شناخت کنندگان، اور Hermes کی دستاویزات سائٹ میں اب بھی کہیں کہیں "Hermes" لکھا
ہوا ہے۔ ماڈیول کا ڈھانچہ (`devbuddy_cli/`، `devbuddy_constants.py`، `devbuddy_state*.py` وغیرہ)،
`devbuddy` CLI کمانڈ، ڈیفالٹ ڈیٹا پاتھ، اور اسٹارٹ اپ بینر/سکن — یہ سب حقیقی معنوں میں نام تبدیل
اور تصدیق شدہ ہیں۔

یہ بند ترقیاتی (closed-development) سافٹ ویئر ہے — فی الحال بیرونی تعاون قبول نہیں کیا جا رہا۔
